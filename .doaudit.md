# Opakovaný komplexný audit

## Cieľ

Vykonaj opakované behy hĺbkového komplexného auditu podľa [`.audit.md`](.audit.md). V každom kole implementuj všetky bezpečné a relevantné navrhnuté opravy a vylepšenia.

## Postup

1. Spusti audit podľa kontrolného zoznamu v [`.audit.md`](.audit.md).
2. Zaznamenaj všetky nálezy vrátane ich závažnosti, príčiny a odporúčanej opravy.
3. Implementuj opravy a vylepšenia nájdené v aktuálnom kole.
4. Over zmeny relevantnými kontrolami, minimálne lintom, buildom a funkčnými alebo produkčnými kontrolami podľa rozsahu zmeny.
5. Zapíš výsledky, vyriešené nálezy a poznatky pre ďalšie behy do [`.audit.md`](.audit.md).
6. Opakuj kroky 1 až 5, kým audit nebude nachádzať žiadne nové opraviteľné chyby alebo bugy.

## Bezpečnostné pravidlá

- Nevykonávaj nebezpečné alebo nekompatibilné automatické opravy, napríklad `npm audit fix --force`, bez samostatného posúdenia ich dopadov.
- Známe výnimky a nálezy, ktoré nie je možné bezpečne opraviť, zdokumentuj spolu s odporúčaným ďalším postupom.

## Dokončenie (povinné vždy)

Po úspešnom ukončení všetkých auditných kôl **vždy** vykonaj celý tento záver — bez pýtania sa používateľa. Audit nie je hotový, kým nie je overený živý deploy.

1. Skontroluj finálny diff a stav repozitára (`git status`, `git diff`).
2. **Commitni všetky relevantné zmeny** z auditu (opravy kódu, `.audit.md`, assety, konfigurácia, skripty). Necommituj lokálne IDE/Cursor súbory (napr. `.cursor/`), tajomstvá ani build artefakty (`.next/`, `out/` ak sú ignorované).
3. **Pushni** commit(y) do `origin/main` (`git push origin main`).
4. **Sleduj deployment** cez GitHub Actions (`gh run list` / `gh run watch`) až do úspešného dokončenia workflow `Build and deploy to arenibus.polascin.net`.
5. **Verifikuj produkciu** na https://arenibus.polascin.net/:
   - HTTP odpoveď homepage (očakávané `200`),
   - relevantné funkčné kontroly podľa rozsahu zmien (napr. `DEMO_VERSION` v HTML, `/robots.txt`, `/sitemap.xml`, demo odkaz),
   - pri zlyhaní CI alebo smoke testu oprav a zopakuj kroky 2–5.
6. Do správy pre používateľa uveď commit hash, URL GitHub Actions runu a výsledok produkčnej verifikácie.
